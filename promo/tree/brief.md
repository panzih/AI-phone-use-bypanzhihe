# 纸盒 · 为什么每步只发控件树，不发截图（28 秒）

1920×1080 / 30fps / 28.000s / 无口播 / 120 BPM 56 拍。

## 论点

> 截图不是贵在 token，是贵在逼模型自己猜坐标。

只讲体积会被懂行的人反驳（图在多数接口按尺寸折 token，单张不算多），
所以全片的转折放在 11 秒那句「可它得自己看出：按钮在哪」。

## 分镜

| 时间 | 镜头 | 内容 |
|---|---|---|
| 0–4 | 它看见了什么 | 左：一张真实截图；右：三行真控件树文本；中间「还是」 |
| 4–11 | 做法一 · 发截图 | 截图右侧流出一条 base64 字符带，铺满整行；689 KB vs 6–20 MB |
| 11–16 | 猜坐标 | 放大安装器的 INSTALL 按钮，绿虚线标真实可点区，红点偏在外面 |
| 16–23 | 做法二 · 控件树 | 五行真 dump 逐行落下；922 字 ≈ 1 KB；同一屏截图 689 KB |
| 23–26 | 边界 | 控件树读不到时返回的那句原文；这时才发图 |
| 26–28 | 收尾 | 「不是省那点流量 / 是别让它去猜」 |

## 数据来源

| 数 | 怎么来的 |
|---|---|
| 689 KB / 530 KB / 183 KB | 四张真机截图的实际字节数；base64 后 ×4/3 |
| 6–20 MB | 30 步 × 单张 200–690 KB |
| 922 字 / 25 个元素 | 模拟器开 Android 设置页，`uiautomator dump` 抓到 64 个原始节点、23 KB XML，按 `UiTreeParser` 的规则（≥24×24、有文字或可点、上限 60）折算成 25 行 |
| 5 行示例文本 | 就是上面那次 dump 的前几行，`Settings` / `Search settings` / `Network & internet` 都是真的 |

## 两个坑（都真踩了）

- **大图逐帧缩放会让确定性检查失败**：同一帧两次渲染差 0.10% 像素。改成启动时把截图缩进离屏画布、逐帧复用同一份位图，就稳定了。
- `logo()` 忘了定义，收尾帧直接报 `ReferenceError`——只渲前两镜时看不出来，改完要整片跑一遍。
