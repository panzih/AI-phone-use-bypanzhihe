# 纸盒 0.16.0

> **不再"替模型认输"，也不再一上来就糊一条悬浮窗。**
> 这一版修的全是真实使用中会让人误判的地方：谁卡住了、错误说什么、第一步做什么。

## 端侧不再硬停「可能卡住」的任务

- 以前：端侧连续 3 次提示"界面没变化 / 同一批动作"之后会**直接结束任务**。
  实测里模型的正确动作刚排进下一轮，端侧的第三次提醒先到了 —— 任务被终止，
  用户看到的是「卡住了：界面已经连续 N 步没有任何变化」。
- 现在：每次只把事实注入上下文，措辞随次数加重（第 4 次起写「这已经是第 N 次提醒」），
  **不强制停**。真正的兜底交给步数上限和用户自己的「接管」。
- 同时改掉了那句会误导人的收尾文案：不再暗示"界面点不动、需要你输入密码" ——
  界面可能是好的，问题在模型原地打转。要区分两种情况，由模型在 `failed` 的
  summary 里说清。

## 第一步先选通道，悬浮条等你选完再出现

- 系统提示词新增「第一步：先选在哪儿操作」：前台主屏 / 后台副屏 / 内置浏览器，
  三条路各自怎么进、什么时候用，由模型自己挑。
- 第一步的 user 消息里会带上这三条路**当次是否可用**（没配 Shizuku 就明说副屏走不通）。
- **第一步不再弹悬浮窗**。悬浮条要等模型选定通道、并且确实在**前屏**操作时才出现；
  副屏（后台）和内置浏览器两种通道都不显示 —— 主屏还给用户，网页也别被盖住。
- 换通道（`move_app` / `browser_open` / 回迁）后，下一步会自动纠正显示/隐藏。

## 地址填错不再喷 Java 异常

- 「获取模型列表」失败时，以前会直接显示
  `获取失败: no protocol: http://10.0.2.2;8899/v1/models` —— 一句英文异常，
  用户看不出是冒号打成了分号。
- 现在先校验 scheme，再用中文说清：地址格式不对 / 域名解析失败 / 连不上某主机 /
  超时 / HTTPS 握手失败，每种都给下一步该做什么。聊天通道同样的错误也一并翻译。
- 顺手修掉了一个易踩点：地址里混进空格或中文标点时，报错会直接把它指出来。

## 悬浮窗提示不再是常驻红字

- 没开悬浮窗权限时，那条说明以前用错误样式（红）常驻在对话里，看着像出故障了。
- 现在用系统消息样式显示一次，文案也改成"任务照常跑，进度看通知栏"。

## 没改的部分

- 历史截图仍然**逐步原样重发**。这不是浪费：OpenAI / Anthropic / DeepSeek 的
  前缀缓存都要求**整个前缀逐字节一致**（图片也算在内），不重发反而会让从断点
  之后的全部历史按未命中计价。详见 `else/reference/deepseek-缓存机制与图片.md`。
- 动作协议、设置项、数据格式不变，可直接覆盖安装。
