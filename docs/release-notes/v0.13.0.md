# 纸盒 0.13.0

> **这一版只改发布签名，功能与 0.12.5 一致。** 但要装对包，先看下面两分钟。

## 先选包

每个 Release 附两个安装包，**同一个应用，手机上只能装一个**：

| 附件 | 谁该装 | 结果 |
|---|---|---|
| `-legacy.apk` | 已经在用 0.12.5 及更早版本 | 直接覆盖安装，**设置、对话、记忆全部保留** |
| `-official.apk` | 全新安装，或愿意重装一次 | 正式签名，从此升级不断档；装之前必须先卸载旧版，**本地数据会清空** |

装错了不会出怪毛病，安卓只会拦一句「签名不一致，无法安装」。

## 为什么换签名

0.12.5 及更早的版本是用一把**私钥随仓库公开**的开发者密钥签的。谁都能签出同签名的包，
安卓会把它当成同一个应用，直接覆盖安装在你的手机上，数据还在、界面照旧——所以那把签名
已经不能代表「这是官方包」。这版起正式线换成独立密钥，私钥只存在构建机和 GitHub Secrets 里。

代价是签名变了，老用户没法一步升到 official 包，所以保留了 legacy 线做过渡。

## 升级路径

- **legacy 用户**：以后照常收 legacy 更新，什么都不用做；
- **想转到 official**：卸一次旧版，装 official 包，之后一直走 official；
- **新用户**：直接装 official。

两条线**功能同步发布**，legacy 不会落后。

## 一个容易踩的点

自动检查更新会按包自己的签名走对应渠道：legacy 包只会收到 legacy 更新，
official 包只会收到 official 更新。这样不会出现「下载到一个装不上的包」。
所以从 legacy 换 official 只能手动卸载重装，App 内不会代劳。

## 安装

- 直接装：把 apk 传到手机，允许「未知来源」，点安装；
- adb：`adb install -r <包名>.apk`
  （Android 15 上覆盖安装可能解绑无障碍服务，装完到「权限」页重新开启。）

## 验证

- 单测、lint、debug 构建在 CI 通过；
- 两个包的签名指纹在 CI 用 `apksigner` 校验过：official 不是那把公开的开发者密钥，
  legacy 与 0.12.5 及更早版本一致（否则老用户装不上）；
- 数据格式未变，0.12.5 → 0.13.0 不需要迁移。
