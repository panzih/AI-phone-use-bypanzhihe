## 🔴 高：会产生错误行为

### 1. 副屏模式下 `open_app` 之后误按 HOME，把刚打开的应用顶掉

- **位置**：`AgentRuntime.kt:155`（`verifyLeftAfterOpenApp`）
- **现象链**：
  1. `verifyLeftAfterOpenApp()` 没有像 `yieldForegroundIfNeeded`（`AgentRuntime.kt:139`）那样加 `isVirtualDisplay` 护栏；
  2. 副屏模式下 `ChannelController.currentPackage()` 恒返回 null（`ChannelController.kt:293`）；
  3. 于是走到 `pressHomeToYield()` → 经 DisplayChannel 对**副屏**发 `input -d <vdId> keyevent 3`（`DisplayChannel.kt:366`）；
  4. 迁移成功后 `onChannelSwitched` 把 `foregroundYielded` 清成 false，所以**每次迁移后的第一个 `open_app` 必中**——刚在副屏上打开的应用被顶回副屏桌面。
- **连带**：ADB 模式 + 无障碍未连接时同理（currentPackage 恒 null → 在主屏上补按 HOME，把启动成功的应用也顶掉）。
- **连带（效率）**：`awaitStable(OPEN_APP)` 在这两种通道下永远确认不到"到达"，每次白等满 2.5s 硬顶（`OPEN_STABLE_HARD_MS`）。
- **修法建议**：`verifyLeftAfterOpenApp` 开头补 `if (controller.isVirtualDisplay) return`；对"读不到前台"的通道（currentPackage 返回 null）应跳过补按 HOME，而不是当成"没切走"。

### 2. LONG_PRESS 编号定位成功后，节点级长按失败的回退打在 (0,0)

- **位置**：`AccessibilityChannel.kt:413-417`
- **现象**：`hint`/编号已定位到节点，但 `svc.longClickNode(node)` 返回 false 时，回退手势用 `action.x / action.y` —— 模型按编号给动作时这两个值是 0，长按落在屏幕左上角。
- **佐证**：DOUBLE_TAP 在同文件 421-446 行修过一模一样的 bug，注释原话「⚠️ 这里原来直接用 action.x / action.y，完全忽略了 index」—— LONG_PRESS 漏改。
- **连带**：水波纹 `onPoint` 画在节点中心，真实点击在 (0,0)，视觉反馈与实际落点不符。
- **修法建议**：回退手势改用已定位节点的 `rect.centerX/centerY`（与 DOUBLE_TAP 的修法对齐）。

### 3. 同一步内截图被重复发送（白烧 token）

- **位置**：`AgentModelExchange.kt:99`（`var pendingImage: ByteArray? = autoImage`）与 `:194`（`history.add(ChatTurn(USER, userText, pendingImage))`）
- **现象**：`pendingImage` 拼进 history 后**没有清空**。同一步里模型再要一次技能或截图（`continue@ask`）时，下一轮 user 消息把**同一张图原样再附一遍**；need_image 拿到的新图在随后的技能轮里也会重复。
- **影响**：副屏模式每步自动带图，撞上 `use_skill` 就是双倍图片 token；与 ChatTurn 的设计注释（"图片跟着它所属的那条消息"）矛盾。指纹一致所以不影响缓存命中，纯粹是浪费。
- **修法建议**：`history.add(...)` 之后立即 `pendingImage = null`（截图失败分支在 488 行已经是这么做的）。
- **⚠️ 2026-11-09 复核结论：此条回退，不采纳。** 不重发同一张图会改变该回合的请求字节，
  服务端上下文前缀缓存从图片位置起全部失效；缓存全废的代价大于重复发送的图片 token。
  现状是**有意重复带图**，见 `AgentModelExchange` 里 `pendingImage` 的注释。

### 4. 坐标手势回退存在竞态：点成功却报失败、中止整批

- **位置**：`AccessibilityChannel.kt:326-335`
- **现象**：`svc.tapAt(...) { ok = it }; Thread.sleep(120); if (!ok)` —— 回调是主线程异步回来的，120ms 内没到就误判失败：返回"点击失败"→ 执行器默认**中止整批**（`p.continueOnError == false` 时），而实际那次点击稍后照样落下去，存在双击风险。
- **额外问题**：`ok` 是普通捕获变量，跨线程读写无可见性保证；同文件其它动作都走 `doGesture`（latch + 4s 超时），唯独这里手写。
- **修法建议**：改用 `doGesture { cb -> svc.tapAt(x, y, cb) }`，与其他动作一致。

## 🟠 中

### 5. `optString` 遇到 JSON `null` 返回字符串 `"null"`

- **位置**：`LlmClient.kt:577-578`（`accumulateSse`）、`:1030-1031`（`parseResponse`）
- **原因**：Android org.json 的已知行为——字段值为 JSON null 时 `optString` 返回 `"null"`（4 个字符）而不是默认值，`isBlank()`/`isNotEmpty()` 都拦不住。
- **影响**：上游回 `"content": null` 时（推理模型/工具调用响应常见），回复变成字面 `"null"`，既不走 reasoning_content 兜底也不判空，最终表现为"模型连续 N 次没给出能执行的动作"。
- **修法建议**：取值前先 `optJSONObject(...).isNull("content")` 判断，null 当空处理。

### 6. 免费模式下语音探针报文不符合 v2 契约，结果必然失真

- **位置**：`LlmClient.kt:708`（`probeAudio`）
- **现象**：探针 body 没有 `stream:true`、没有逐字 `tools`（read/shell）、system 里没有 `<env>` 块——按项目自己在 FreeLaneWire 钉死的 v2 契约，这些缺失会直接 403 FreeTierError。
- **影响**：免费模式的探针永远报"通道拒绝/不收音频"，与音频能力无关，误导排查方向。
- **修法建议**：免费模式下探针要么按 v2 契约补齐报文，要么直接标注"免费通道暂不支持语音探针"。

### 7. 屏幕分辨率永久缓存，横竖屏切换后坐标口径失真

- **位置**：`AccessibilityChannel.kt:50`（`cachedSize`）；`ChannelController.release()` **全工程无调用方**（已 grep 确认）
- **现象**：缓存只在 `release()` 清，而没人调它。Agent 的注释声称"分辨率每步重读：横竖屏切换都会改它"，实际拿到的是进程生命周期内的旧值。
- **影响**：旋转后控件树屏外过滤、坐标夹紧（`ActionParser.clamp`）、TapReview 裁剪全部按旧尺寸算。
- **修法建议**：`screenSize()` 每步重读系统真实尺寸，或按 `resources.displayMetrics` 变化失效缓存。

### 8. 任务收尾后的日志把消息写两遍

- **位置**：`AppLog.kt:110`
- **现象**：`stamped` 已等于 `"[时间] $message"`，closed 分支又拼一次 `"$stamped [收尾后] $message"`，run.log 里同一句话出现两次。
- **修法建议**：改为 `"$stamped [收尾后]\n"` 或只拼一次 message。

## 看过、确认没问题的重点

- 免费通道 v2 契约链路：session 持久化（`FreeLaneWire.session()`）、`gatewayHeaders` 逐项、逐字 read/shell 工具定义、`<env>` 块，与 `FreeLaneBodyTest` / `FreeLaneHeadersTest` 三方一致
- 上下文缓存前缀设计：ChatTurn 带图逐字重发、指纹链跨任务续接（`seedFingerprints`）、`ContextStore` 原子写 + 备份回退
- 防幻觉三道闸：blind finish（新任务第一步+旧历史）、unverified finish（无动作+无界面变化）、executedActions==0 收尾
- 高风险词表 + 模型二次确认（fail-closed）与端侧弹窗建议（云端决定权）
- 崩溃报告落盘（`CrashGuard` 同步刷盘、防覆盖命名）与导出脱敏（`LogSanitizer`）
- 设置加密存储（Keystore AES-256-GCM、明文迁移）
- 悬浮窗 Android 12+「不信任触摸」0.80 遮挡红线的合成计算（0.765 / 0.7768）
- 定时任务令牌交接（不经过 Intent 的进程内交接，堵第三方伪造）

# 附：免费模型"不能用"的诊断与修复（2026-11-04 补记）

## 结论

- **网关侧报文契约是对的**：按 App 代码逐字节复刻请求实测，返回 `429 FreeUsageLimitError` 而非 `403 FreeTierError`——按本项目判据（FreeLaneWire 头注释、docs/free-lane-wire.md）说明已过 v2 闸门。**用户本机实测免费模型可用**，证实报文/网络链路无问题。
- **"不能用"的根因在 App 的响应处理**：Android org.json 的 `optString` 对值为 JSON `null` 的字段返回**字符串 `"null"`**（不是空串）。免费池的推理模型（网关从 Anthropic/Gemini 归一成 OpenAI 流）delta 常带 `"content": null`，于是回答被拼成 `"nullnullnull…"` → `ActionParser` 永远解析不出 JSON → 连续 5 次"解析失败" → 任务必死。**模型本身是好的，App 把好回答解析坏了。** 项目在 `UpdateChecker.parseInfo` 里记过同一个坑，但 LlmClient 这条路漏了。

## 已修复（本轮）

| 修复 | 位置 | 说明 |
|---|---|---|
| ① `content/reasoning_content` 为 JSON null 时按空处理 | `LlmClient.accumulateSse` + `parseResponse` | 先 `isNull()` 再取，杜绝字面 "null" 混入回答；空回答照旧走思维链兜底/重发 |
| ② 模型只调 read/shell 占位工具、无文字时回灌提示 | `LlmClient.accumulateSse` | 老逻辑攒成空内容 → 三连重发 → 任务失败；现在回一句"占位工具不可调，请输出本轮 JSON"，任务继续、模型自纠 |
| ③ 同一步内截图不再重复发送 | `AgentModelExchange.askModel` | ~~`pendingImage` 拼进 history 后立即清空~~ **2026-11-09 复核回退**：不重发会破坏上下文前缀缓存命中，代价更大，保留重复带图 |
| ④ 语音探针报文补齐 v2 契约 | `LlmClient.probeAudio` | 免费模式补 tools + `<env>` + stream:false，探针不再必然 403 误报"不收音频"；`AudioProbe.describe` 增加 `FreeUsageLimitError` → "额度用完" 的翻译 |
