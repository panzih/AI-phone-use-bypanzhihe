# 纸盒 · 宣传片（90 秒解说版）制作方案

**成片**：`docs/promo/纸盒-宣传片-90秒解说版.mp4`（桌面也放了一份）
**规格**：1080×1920 竖屏 · 30fps · H.264 + AAC · **90.6 秒** · 带中文解说与配乐
**上一版**：`docs/promo/纸盒-宣传片.mp4`（60 秒，只有字幕没有解说，保留不动）

---

## 一、这支片子想解决什么

上一版是**默片**——九段字幕轮播，靠观众自己读。这次的三条改动：

1. **有解说**：全片一条人声旁白（macOS `say` 的 Tingting 音色，190 字/分）。
   字幕退成"补充信息"，不再和人声重复念同一句。
2. **有真任务**：补到一段**真机实录**（模拟器上跑 0.10.7，`tools/mock_llm.py` 当模型）——
   点发送 → 悬浮条推步数 → 它自己把系统「设置」打开了。上一版缺的正是这一段。
3. **时长拉到 90 秒**，每个卖点都有独立段落；段落切换全部对齐解说句读。

定位：给"知道 AI 能操作手机、但没试过"的人看。不吹参数，只回答三个问题——
**它是什么、跑起来什么样、装起来麻烦不麻烦。**

## 三、解说词（全片一条声轨，逐段卡点）

朗读参数：`say -v Tingting -r 190`。每段解说在场景开始后 0.5s 进（开场 1.6s 让 logo 先画完），
场景长度 = 解说长度 + 尾留白。所以不会出现"话说完了画面还在空转"或者"画面切了话没说完"。

| 段落 | 解说词 | 时长 |
|---|---|---|
| 开场 | 手机里有一半的事，本来不该你亲手点。 | 3.6s |
| 痛点 | 关 Wi-Fi、清缓存、把一段话复制出来——这些动作你重复过太多遍，每次还得自己盯着屏幕，一下一下点过去。 | 10.4s |
| 它是怎么做的 | 纸盒换了个做法。你说一句话，它自己看屏幕、自己决定点哪里，一步一步做完。不用 root，也不用连着电脑。 | 9.8s |
| 主界面 | 打开就是这样一个界面：一个输入框，一个发送键。 | 4.6s |
| 跑起来 | 按下去，它就开始干活。屏幕下方那条写着它在干嘛，然后它自己打开了设置——你一根手指都没碰。 | 9.2s |
| 模型 | 模型自己选。填自己的 Key，接 DeepSeek、OpenRouter 或者本机 Ollama 都行；不想花钱，就用内置的免费通道，开箱就能跑。 | 11.2s |
| 安全 | 它只在你手机上跑。Key 加密存在系统 Keystore 里，没有广告，没有统计，每一步都留下日志。 | 8.4s |
| 三步 | 上手只要三步：装一个 APK，开一次无障碍权限，然后说一句话。 | 7.3s |
| 收尾 | 不绑定厂商，不限定机型。装一个 APK，开一次无障碍权限——然后就不用管了。 | 8.2s |

字幕原则：**不重复人声**。人声说的是句子，屏幕上只留数据点
（`DeepSeek · OpenRouter · 本机 Ollama 都行`、`不想花钱？内置免费通道`、
`接口地址 + API Key + 模型名`）。

## 四、可执行的生产链路

源码都在 `docs/promo/v2/`，只用系统自带框架（CoreGraphics / CoreText / AVFoundation），
没有第三方依赖，也没有联网素材。

```bash
cd docs/promo/v2

# 1) 解说 + 时间线（改文案只改这个脚本里的 SEGS，重跑即可）
python3 make_timeline.py          # → audio/s1..s9.aiff + timeline.json

# 2) 画面（读 timeline.json 决定每段起止，所以改文案不用改代码）
swiftc -O -o /tmp/promo2 render2.swift && /tmp/promo2      # → paperbox-promo-v2.mp4（无声）

# 3) 声音（解说 + 带 ducking 的配乐；配乐是按采样点算的，无音频素材）
swiftc -O -o /tmp/promomix mix.swift && /tmp/promomix      # → /tmp/promo2.wav

# 4) 合成
swiftc -O -o /tmp/promux mux2.swift && \
  /tmp/promux paperbox-promo-v2.mp4 /tmp/promo2.wav 纸盒-宣传片-90秒解说版.mp4
```

耗时（这台 Mac）：画面 ~110 秒，声音 ~20 秒，合成 ~10 秒。

**踩过的坑，写在这里省得重踩：**

- `AVAudioFile` 写 WAV 时，文件头里的 data 长度是**对象释放时**才回填的。顶层变量活到
  进程结束 → 出来的 wav 是"0 字节 / 0 秒"的头，`afconvert` 和 AVFoundation 都读不进去
  （合成直接报 `-12780`）。现在写文件那段包在函数里，出函数即释放。
- 模拟器录屏里**点发送之后的前 9.4 秒画面是静的**（模型还没回第一句），从 0s 取会拿到
  "还没开始"的空屏。第 5 段是从录屏 **9.9s** 处读的。
- 模拟器的 `input text` 打不进中文（`ShellCommand.sendText` 抛 NPE），所以录屏里那句任务是
  `turn off wifi`。中文任务只能上真机录。
- 设置页顶部「自定义 / 免费」两个按钮的样式**是写死的**（`OutlinedButton` / `Button`，
  不跟 `useFreeModel` 走），所以截图里看起来永远是"免费模型被选中"。这一版干脆把那一行
  裁掉了，只留功能字段。**这是个真 bug，建议单独修**（`SettingsScreen.kt:321-328`）。

## 六、验收怎么做的

1. **逐段抽帧看**：按场景中点抽帧（3.3 / 12.7 / 15.5 / 24.6 / 33.4 / 38.2 / 39.5 / 41 / 50.5 /
   55 / 68 / 77 / 88 s），逐帧核四件事：①字幕齐全 ②两条字幕不叠在同一位置
   ③手机壳里是真实界面而不是黑屏 ④文字不出界、不被裁成半截字。
   **第一版就靠这一步抓到三处**：主界面标注压在手机上沿、设置页卡片把标题切成半截、
   旧版悬浮窗截图（`第1/30步 等待25000ms`）和新界面混在一起。
2. **音轨**：`afinfo` 核 90.6s / 44.1kHz / 立体声；`rms` 工具按 0.5s 打一次 dBFS，
   确认解说落在每段起始位置、说话段落比配乐高 11dB 以上（配乐 -26dBFS / 人声 -15dBFS）。
3. **时长**：`AVAsset` 读 90.57s，满足"不少于 1 分钟"。

## 七、已知取舍

- **模拟器合成器中途卡死**：任务跑到第 ~14 秒时 BlueStacks 不再重绘（已知问题，不是 App
  的锅），所以第 5 段后 7 秒是定格「设置」页 + 慢推镜撑住的。**真机重录一段**
  （悬浮条一路推到底 + 完成卡 + 落点水波）替换这 7 秒，整片会强一个档次。
- 段落之间是 0.55s 交叉溶解，不是硬切。想要更"脆"的节奏，改 `render2.swift` 里的 `FADE`。
- 只做了 9:16 竖屏。要投 B 站横屏得重排布局（`W/H` 是常量，没有做参数化布局）。
