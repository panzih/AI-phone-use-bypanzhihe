## 0. 感知层（命中率地基）

> 来源：2026-10-31 对照 `ccch1mneyyy/dsh-Go` v1.0.4（Flutter + 内置 proot Linux，195MB）的技术拆解。
> 结论：**真正拖累命中率的不是"截图上没画编号"，而是快照本身**——元素上限、截断顺序、
> 文本没有语义结构、密码不屏蔽。截图编号排在最后，因为它依赖前两项先做对。
>
> 2026-11-01 追加：设计见 [agent-loop.md 第 5 节](../architecture/agent-loop.md) ——
> 每步注入"操作环境卡"，由模型指定下一轮要控件树还是截图。

- [ ] **每步注入「操作环境卡」**（第一阶段，改 `AgentPrompt` / `AgentStepObserver`）：
  固定输出"模式（操作软件 / 内置浏览器）· 屏幕（前台 / 后台）· 本轮输入 · 下一轮可选"。
  现在这些信息只在"读不到树"时用 `noTreeReason` 的常量说一半，正常步骤里完全缺失，
  模型不知道自己在前台还是副屏，也不知道换屏了编号会失效。
- [ ] **`view` 字段：模型指定下一轮要树还是图**（第一阶段，改 `ActionParser` / `AgentModelExchange`）：
  `{"view":"tree"|"image"|"both"}`，一次性生效，不写就是树；`need_image` 继续兼容。
  本轮无动作时立刻重问且不计步（复用现成机制）；有动作时下一步生效。
  **不做成常驻状态**：历史图每次请求都要重发，常驻会让 token 按步数线性上涨。
- [ ] **给图时同步读树 + 阈值建议**（第一阶段）：给图的同时读一次树，只计数不发列表。
  `count >= 10` 建议下一轮改用树；`count < 5` 明说"只能按图坐标点"；读不到根节点不追加计数
  （别把"看不到"说成"空页"）。5 和 10 之间不提示 —— 每步都劝模型换视图只会干扰判断。
- [ ] **浏览器模式的环境说明**：`BrowserChannel` 读的是 DOM 摘要，不是系统无障碍树。
  "WebView 只读到几个退出按键"多半是通道没切（`mode` 还是 `A11Y`，读到的就是 `BrowserActivity`
  自己的工具条）。环境卡要如实报模式，并在"操作软件模式 + 前台是 `BrowserActivity` + 元素极少"
  时明确建议先 `browser_open`。
- [ ] **`move_app` 动作（第二阶段）**：`{"action":"move_app","to":"background"|"foreground"}`，
  复用 `ChannelMigration` 的迁出/回迁路径；需要 Shizuku READY，不够就返回中文原因；
  **单任务最多 3 次**（防模型因为某一屏显示异常而每步搬一次）。
- [ ] **元素上限与截断顺序**：`TREE_LIMIT = 60`（`AccessibilityChannel.kt:737`），且遍历是
  `addLast` / `removeLast` 的**逆序**深度优先（`UiNode.kt:196-238`）。撞上限时先被丢掉的
  可能是屏幕顶部（标题 / 返回 / 搜索框），编号顺序也不是从上到下的阅读顺序。
  改法：空间排序 + 分区预算 —— 结构元素（可点 / 可输入 / 可滚）全留，装饰折叠，
  超预算输出"…另有 N 项"。**不要照抄对方的 2000**：它配的是 3000 字符预算，
  单看节点数只会把提示词撑爆。
- [ ] **屏幕文本的语义结构**：`UiNode.describe()`（`UiNode.kt:53-75`）现在只有
  `[n] 类名 "文字" @(x,y) [标志]`，标签截 40 字，没有中文角色、没有区域分组、没有卡片归属。
  要补四件事：①中文角色（按钮 / 输入框 / 标签 / 开关）；②顶部 / 中部 / 底部分区 +
  可滚容器缩进；③可点击行吸收非交互后代文字（TalkBack 的朗读单元，也是模型的语义单元）；
  ④`⚠` 敏感标记与 `+` 相对上一帧新增标记。
- [ ] **节点字段缺失**：`UiNode`（`UiNode.kt:17-36`）没有 `isPassword` / `selected` /
  `heading` / `stateDesc` / `rangeInfo` / 滚动能力位。直接后果：滑块类任务
  （"把亮度调到 40%"）读不到当前值只能盲拖；`checked` 之外的状态模型一概看不见。
- [ ] **密码框内容不屏蔽（安全项，不只是准确率）**：没读 `AccessibilityNodeInfo.isPassword`，
  `text` 原样进提示词、也原样进导出日志；敏感判断只靠按钮文字命中词表
  （`AgentLimits.highRiskReason`），字段本身没有标记。
  要做的是节点层加 `isPassword` → 渲染时替换成 `••••`、写日志前丢弃原始值。
- [ ] **祖先查找缺 bounds 命中校验**：`AutoService.kt:511-527` 只要 `isClickable` 就
  `performAction`，没有校验这个父节点是否真的覆盖落点。会点到"没覆盖落点"的外层容器：
  不报错、界面不动，正是日志里"已执行但界面没变化"那类难查问题。补一句
  `rect.contains(centerX, centerY)`（层数 5 层比对方 4 层宽，但换不来收益）。
- [ ] **亮屏 / 解锁 / 无障碍连接闸门**：全仓没有 `isInteractive` / `KeyguardManager` 的调用。
  灭屏、锁屏时 Agent 照常读树、发请求、点空屏，白烧一轮 token。
  不可用时直接给模型一句中文原因（"屏幕已关闭，只在亮屏解锁时操作手机"），别让它自己猜。
- [ ] **抓树的时间预算**：`keepNodesDetailed` 只有节点数上限，**没有 `budgetMs`**；
  observe / 动作 / 翻页没有各自的时间上限，也没有 abort 代际（只有 `stopRequested` 布尔）。
  深树（WebView、小程序、大列表）下 `readTree()` 是同步阻塞，一旦慢就是整步卡死，
  而不是"这一步超时、如实上报"。
- [ ] **`setText` 重试链与 IME 回车**：`AutoService.kt:548-553` 一次 `ACTION_SET_TEXT`
  失败就结束；全仓没有 `ACTION_IME_ENTER`。改成 focus → setText → 失败则 click → refresh →
  再 setText；搜索框另给一个"回车"动作。
- [ ] **近黑帧判定**：`AutoService.explainError` 只处理系统错误码，某些安全窗口返回的是黑图
  而不是直接拒绝，现在会原样发给模型，被当成"空屏"。黑屏也要按 secure 处理。
- [ ] **提示词 / 工具集哈希测试**：`AgentPrompt.VERSION` 是手改的，没有任何测试钉住提示词文本。
  一旦误改，服务端 KV cache 从第一个改动 token 起全部作废，只表现为"变慢变贵"，很难定位。
  工具名 / 参数枚举同理：发布后只增不改。
- [ ] **`collect`（批量翻页收集）**：现在只能一步一 scroll、每步重新问一次模型。
  读长列表（订单、评论、通讯录）成本是对手的 5~10 倍。给一个带页数 / 时间 / 无新增
  三种停止条件的批量观察。
- [ ] **意图类工具**：只有 `open_app` / `list_apps` / `read_setting`。设闹钟、短信草稿、
  导航、分享、读写剪贴板现在都得靠 UI 点，成功率低、步数高。
- [ ] **截图编号（排最后）**：`Canvas.drawText` + 图上↔屏幕几何映射，编号必须和文本同一套。
  **前提是先做完前两项** —— 文本编号还在逆序截断时把编号画到图上，等于把错误放大一倍。
- [ ] **副屏的控件树与免 Shizuku 通道**（长期，短期不改）：副屏现在只能截图猜坐标
  （平台不给第三方读副屏无障碍树，实测记录见 `DisplayChannel.kt:24-58`），且强依赖 Shizuku。
  对方的 self-ADB（通知里输配对码）是我们完全没做的部分。先确认 shell 侧能不能枚举
  非默认显示器的窗口，再决定做不做。

## 5. 明确不做

- **高风险动作的强制人工确认**：不做"每次支付/发送/删除前都弹一次确认"。
  现行策略是：**默认直接拦截**；用户在设置里显式打开「允许 AI 执行高风险操作」后，
  每个高风险动作仍要过一次**独立的模型二次确认**（请求失败/输出无法解析一律拒绝，fail closed），
  结果写进运行日志。这样默认状态不会无限制执行，也不需要用户每一下都盯着点确认。
- **端侧自主决策**：端侧只执行云端点名的动作；端侧弹窗规则只给建议，点不点由云端决定。
  结论性判断只做建议，最终决定权归模型。
- **引入第三方运行时依赖**：运行时只用 AndroidX + Shizuku，不加网络框架、依赖注入框架。
  `androidx.test` 只用于 `androidTest`，不进 APK。
- **MCP 协议 / 插件市场 / 远程连电脑**：这三项是"接生态"，不是"点得准"，和命中率不是一个维度，
  不该和感知层的工作抢优先级：
  - MCP 的价值在"容器里的 Node 进程"能通过标准协议调手机能力。我们本来就在同一个进程里，
    skill 注册表直接调用，没有序列化开销 —— 这是优势，不是缺陷。真要改，只把 `SkillRegistry`
    的接口 schema 化 + 冻结测试，**不需要 unix socket**。
  - 插件市场是和对方 195MB 的 proot 架构绑死的。我们没有 Node 运行时，"npm 包市场"等于把
    唯一的优势（轻量）交出去。等价的正确形态是"用户自定义技能：一段提示词 + 一组固定动作"，
    本地存、不做远端分发。
  - 远程连电脑是另一条产品线（手机当瘦客户端），做了也不让手机 agent 更准。真要做就复用
    现成 Noise 实现，别自己写密码学。

## 6. 已知限制（不是 bug，别当 bug 报）

- 副屏上的窗口不会交给无障碍，所以副屏只能靠截图 + 坐标，没有元素编号列表。
- `FLAG_SECURE` 的页面（支付、银行）截不到图，副屏上会黑。
- `input text` 不支持中文，模拟器输入法也只有英文，驱动界面时只能敲 ASCII。
- 免费通道有速率限制，额度用尽时网关返回 429；换个时间段或填自己的 Key。
- 上下文缓存是"完整匹配一个缓存前缀单元"，中间断一条就从断点起全废，所以不能随意裁剪历史。
- 内置浏览器只放行 http/https；`file://`、`intent://`、自定义 scheme 会被拒绝。
- 公网明文 HTTP 默认拦截；本机/局域网地址不受影响。
